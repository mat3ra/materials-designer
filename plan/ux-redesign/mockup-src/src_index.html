A parametric CAD studio for crystals

One document model — materials plus their operation logs — with three synchronized projections (3D, forms, code), one searchable Catalog for every way to create or transform a structure, an Assistant that compiles language into previewable operations, and provenance as the spine of the product. Six screens tell one continuous story: a session named “Silicon slab study”, where a Si bulk becomes a (111) slab, a 3×3 supercell, a P-doped surface with pinned bottom layers — every step recorded, editable, shareable.

EIGHT PRINCIPLES THE DESIGN COMMITS TO
P1Every edit is an operation

Gestures, forms, notebooks, AI proposals — all compile to one recorded operation object. Exactly one history; ⌘Z works everywhere the same.

P2The recipe is the artifact

The timeline is the editable source the structure is computed from — and it exports as a runnable script. Reproducibility is UX, not documentation.

P3Preview before commit

Ghost atoms, dashed future cells, predicted counts before Apply. Engines that can't preview say so and predict what they can.

P4One catalog, many engines

Users pick what; native / notebook / code / AI is a badge on the card, not a different door. The ~25 hidden notebook workflows become visible.

P5Three projections, one selection

Viewport, forms and code are views of the same model; selection and hover flow across all three, both directions.

P6Sets and lineage, not lists

A combinatorial op emits 100 materials; a slab knows its bulk. Trees, set folders, roll-ups and virtualization are the default shape.

P7Crystallographic honesty

Units always visible; crystal vs cartesian is a global mode; symmetry locks dependent lattice fields visibly; conventional vs primitive is labeled.

P8Same core, four costumes

IDE, embedded editor, read-only viewer, picker — one model and component set; only chrome and permissions change.

HOW TO READ THESE MOCKUPS
Controls, top bar of every screen: theme toggle (dark is the product default; light is full-parity — try it anywhere), state switcher on screens with multiple states (also deep-linkable, e.g. 02-catalog.html?state=B), and an Annotations toggle. Numbered pins mark design decisions — hover one, or read the legend panel (click its header to collapse).
What is faked: the 3D viewport is a static SVG of a real Si(111) slab (computed geometry, not clip-art) standing in for wave.js; data is one consistent narrative session. What is real: the layout system, both themes, all chrome, and every interaction pattern annotated. These are self-contained HTML files — no build step, open from disk.
Deliverable of the MD 2.0 UX redesign (v2 track) — runs parallel to the incremental v1.x track (PR #299: status bar, ⌘K palette, basis table, resizable panels). Stack-agnostic by agreement: these screens assume only a capable web stack, a canvas emitting edit-commit events (wave.js), and an in-browser Python sandbox (JupyterLite/Pyodide). The companion document — audit, the five load-bearing decisions (D1–D5), IA rationale, system spine, extension specs, full parity matrix, MVP estimate (~9–10 engineer-weeks) and phased roadmap — is plan/ux-redesign/PROPOSAL.md.
